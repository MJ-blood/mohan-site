首页与作品列表复用作品卡片。预览使用 HTML／SVG 表达已有材料中的知识整理链和协作交接过程，明确工具／记录类别与阶段；不使用虚构截图、用户数据或成果指标。关于页集中说明个人背景、当前关注和工作方式，保留代表内容入口。

## Markdown 发布方式

`content/posts/` 是公开文章输入；`.md` 文件名决定默认地址，允许可选元数据指定标题、摘要、主题、日期与草稿状态。没有元数据的普通 Markdown 也能发布：首个一级标题作为文章标题，首段作为摘要。日期仅展示作者明确填写的信息；现有文章迁移使用真实整理日期 `updated: 2026-10-03`，不补造历史发表时间。

构建统一派生页面、列表、目录、阅读时长和搜索数据；文章旧路由及已有锚点保持。相对 Markdown 链接转换为站内文章链接，引用的图片／PDF 复制到公开资源路径。草稿不进入页面或搜索；私有知识库不自动纳入构建。

本地预览由 Astro 提供；内容集合监听公开内容变化并串行更新，解析失败时页面明确报错，修正文件后恢复。正式网站仍是静态产物，需要构建和部署后更新；当前未配置自动上线或编辑后台。Astro 构建重建 dist/，改名／移除文章、转为草稿或取消附件引用时，旧产物随新构建移除；输出目录只用于生成物。

构建使用 Astro 官方 Unified Markdown 处理器；YAML 元数据经过安全解析与严格校验。标题／摘要回退、自定义锚点、文章相对链接和引用附件属于本站写作契约，由内容插件处理；页面、路由、资源打包与本地服务由 Astro 提供。依赖版本固定在 package.json 和 package-lock.json，仅安装到项目目录。

正文使用系统中文字体与系统无衬线字体；代码使用等宽字体。正文为 17–18px，辅助信息为 12–14px，尺寸、颜色与响应式规则集中在样式文件维护。手机导航支持键盘、Escape 与外部点击关闭。

### 动效与偏好（2026-10-17）

动效控制移到全站页脚，使用“减少动效”按钮及 aria-pressed 表达状态；页头只保留主题切换。继续记住用户选择，支持跨页、返回和同源标签页同步；存储不可用时当前页仍可操作。系统“减少动态效果”优先并在页脚说明。

首页与作品卡片按组轻微上移淡入，创作插画缓慢浮动、连线流动，桌面指针仅影响插画的轻微倾斜；作品卡片悬停轻微抬起，文章列表以背景和标题反馈点击。循环效果只在对应区域可见时运行，离开浏览器标签页暂停；悬停或键盘聚焦的创作卡片停止浮动。系统或页脚减少动效会关闭这些效果，偏好变化时结束进行中的入场动画。

文章正文、目录和搜索结果不使用持续装饰动效；搜索结果立即更新。内容默认可见，入场只作为增强，禁用 JavaScript 时文章、插画链接与导航仍可用。基础排版位于 `src/styles/site.css`，首页与作品插画样式位于 `src/styles/presentation.css`，相应交互由 `src/scripts/presentation.ts` 管理。
## 完成标准

新增一个 Markdown 文件后，无需登记页面或手改列表即可看到文章；只改这个文件，标题、摘要和正文同步更新。验证草稿排除、错误提示、目录、附件、搜索与筛选、保存刷新和并发重建。全部路由及链接可用，正文无需 JavaScript，320–1440px 无页面横向溢出，键盘能操作菜单与查找入口。桌面、手机首页尽早显示最近文章的标题与摘要，归档优先展示内容；200% 字号下内容可读。实际验证记录统一写 README。

## 架构决策（2026-10-17）

用户确认以写作、作品展示为主，逐步增加小工具或订阅入口。采用 Astro + TypeScript + Markdown，当前使用静态输出。TS 分别用于构建时内容处理和编译后在浏览器执行的交互，不代表现在引入后端。

页面通过文件路由组织，布局和文章卡片复用组件，内容查询与展示分开。目录与元数据从 Markdown 派生；content/posts/ 仍是文章正本。只发布实际引用的附件，通过静态资源端点输出，不复制整个内容目录。正文搜索暂时使用归档页内的全文索引；当手机加载明显变慢时再调整索引加载。

自定义内容加载器通过 Astro Loader API 调用标准 Markdown 渲染与 schema 校验。公开内容变动时重载整个小型集合，确保改名、草稿、相对链接和附件共同更新。开发期间载入失败以错误条目阻止文章页继续展示旧数据，修正后重新加载；构建遇错直接失败。Markdown 插件只处理站点写作规则，不承担页面模板或路由。

复杂独立工具出现时可按需接入 Vue 3 + TS；订阅可接成熟服务。需要密钥、用户数据或登录时，增加服务端 API 与相应部署环境，公开内容页面仍可静态生成。若主体转为复杂的登录后应用，再评估 Nuxt 等应用框架。当前不预建账号、数据库、后台或通用插件系统。

使用原生 CSS 变量管理全站主题；页面脚本按主题、动效、导航、归档和文章阅读拆分。框架迁移验收聚焦既有 10 个页面、文章写作契约与桌面／手机行为，当前结果统一记录在 README。原实现的验证记录见 [历史归档](archive/2026-10-03-validation.md)。
